# Правила репозитория архитектуры ORDIN

## 1. Русские названия файлов

Файлы называем понятно для владельца системы.

Хорошо:

```text
01_Главная_карта_системы.drawio
02_Карта_данных.drawio
03_Процесс_от_заявки_до_денег.drawio
```

Плохо:

```text
system_map_final_v3.drawio
new_scheme.drawio
architecture_last.drawio
```

## 2. Одна схема = один смысл

Не смешиваем на одной карте всё подряд.

Отдельно:

- общая карта системы;
- карта данных;
- карта процесса продаж и производства;
- карта AI-ролей;
- карта n8n workflow;
- карта логики Bitrix.

## 3. У каждой важной схемы должно быть описание

Схема отвечает на вопрос «как связано».
Описание отвечает на вопрос «зачем это нужно и как использовать».

## 4. Все изменения фиксируем

Если меняется архитектура — добавляем запись в:

```text
журнал_изменений/Журнал_изменений_архитектуры.md
```

## 5. Не превращать GitHub в склад мусора

Не загружать сюда случайные документы, КП, договоры, выгрузки и временные файлы.

Этот репозиторий только для архитектуры системы ORDIN.
